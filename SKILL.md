# Smart clipping — відбір і нарізка по словах

Довге відео → 5-12 коротких кліпів. Два етапи, **строго по черзі, з паузою на
узгодження між ними**.

| фаза | вхід | вихід | коли |
|---|---|---|---|
| **1 — відбір** | транскрипт з таймкодами | `clips_plan.md` + `clips_plan.json` | одразу як кинули транскрипт |
| **2 — нарізка** | відео + узгоджений план | сирі mp4 + звіт перевірки | тільки після «ріж» / «погоджено» |

**Ніколи не запускай фазу 2 без явного дозволу.** Фаза 1 закінчується планом і
питанням «що правимо?». Відео на фазі 1 не потрібне і не чіпається.

## Чим відрізняється від нарізки по таймкодах

Таймкоди з транскрипту неточні: зсув буває ±10-45 с, а різ «на око» з'їдає
перше слово або тягне хвіст сусідньої фрази. Тут таймкод — лише **вікно
пошуку**. Реальний різ ставиться так:

1. whisper робить пословний транскрипт відео (час на кожне слово);
2. дослівна цитата з плану знаходиться в ньому через difflib;
3. різ = початок першого слова − невеликий буфер, кінець останнього слова + буфер;
4. після нарізки готові файли перетранскрибовуються й звіряються з планом.

# ФАЗА 1 — витягнути текстові кліпи

## Спершу уточни (або візьми з контексту клієнта)

- діапазон тривалості (дефолт 25-90 с);
- скільки кліпів (дефолт 5-12);
- про що кліпи / які теми потрібні клієнту;
- які теми й імена брати **не можна**.

Не вигадуй правила клієнта — якщо їх нема, працюй за дефолтами нижче.

## Три типи кліпів

### `qa` — питання як хук

Питання ведучого лишається в кліпі дослівно, далі одразу відповідь. Між ними
завжди різ (прибирає паузу й «еее») — це **два окремі фрагменти** в плані.
Питання коротке (до ~15 слів) і про одну тему.

```
frag 1  ← питання, дослівно, ціле
frag 2  ← відповідь, з першого змістовного слова
```

### `framework` — цілісна думка зі структурою

Спікер викладає систему або нумерований список («номер один… номер два…»,
«три дні, три тижні, три місяці»). **Один фрагмент, різати всередині
заборонено.** Якщо спікер збився, повторився чи почав спочатку — це не
framework: шукай чисте місце або веди як `story`.

### `story` — історія з різних місць

Найдовший і найбільш монтований тип: 3-10 фрагментів з **різних місць**
запису. Робоча арка:

```
проблема → спроби, що не спрацювали → цифри/таймлайн → чого бракувало → що спрацювало
```

Хук: шокова фраза, самопредставлення з цифрою або чітко сформульована проблема.

## Тверді правила відбору

**Кінцівка закрита.** Кліп закінчується панчлайном, висновком або емоційним
пейоффом. Ніколи на півдумці, ніколи на «…and so, yeah, um». Нема закритого
кінця — не бери.

**Одна сильна фраза.** У кліпі є рядок, який тримає його сам по собі — цитата,
яку можна процитувати без контексту. Нема такої — кліп слабкий, викидай. Це
головний фільтр.

**Довжину не підганяй.** Ріж по завершеній думці, а не «щоб було 30 секунд».

**Хук у перші 3 секунди.** Кліп не починається з «so», «ну», «yeah» і
розгону — перший фрагмент має зачепити одразу.

**Цитуй дослівно.** `text` кожного фрагмента — слово в слово з транскрипту,
включно з «like», «you know», обірваними словами. Не чисти й не переказуй:
фаза 2 шукає ці слова у відео, переказ вона не знайде.

**Не бери, якщо:** спікер плутається у фактах, згадує третіх осіб/бренди без
дозволу, дає медичну/юридичну/фінансову пораду, або тема повторює вже взятий кліп.

## Що віддавати

**`clips_plan.md`** — для людини: номер, тип, тривалість, фрагменти з
таймкодами й цитатами. Це те, що користувач читає й править.

**`clips_plan.json`** — для машини:

```json
{
  "speaker": "Guest A",
  "source_transcript": "interview.txt",
  "clips": [
    {
      "id": "03",
      "type": "story",
      "title": "short-latin-slug",
      "fragments": [
        {"start": "00:12:04", "end": "00:12:15", "text": "дослівна цитата початку"},
        {"start": "00:18:40", "end": "00:18:44", "text": "дослівна цитата наступного шматка"}
      ]
    }
  ]
}
```

`start`/`end` приблизні — лише вікно пошуку. `title` — слаг латиницею через
дефіс, стає іменем файлу.

## Обов'язково перед показом плану

```bash
python3 scripts/validate_plan.py clips_plan.json transcript.txt --fix
```

Перевіряє, що кожна цитата справді є в транскрипті, і вписує таймкоди звідти.
Збіг нижче 85% = переказав замість цитувати. **Виправ і прожени ще раз** —
план з проблемами показувати не можна.

Закінчуй фазу 1 підсумком (скільки кліпів, типи, загальний хронометраж) і
питанням, що правити. Далі чекай.

# ФАЗА 2 — нарізка

Запускається **тільки** після «ріж» / «погоджено». Потрібне відео.

## Крок 1 — пословний транскрипт відео

```bash
python3 scripts/transcribe_source.py "video.mp4" --model medium.en
```

Для не-англійської мови бери мультимовну модель (напр. `medium`). Результат:
`work/video.words.json`. Довго (80-хв відео ≈ 15-25 хв на CPU) — запускай у
фоні. Робиться раз на відео.

Це джерело **часу**; транскрипт користувача — джерело **тексту**.

## Крок 2 — притягнути різи до слів

```bash
python3 scripts/snap_clips.py clips_plan.json work/video.words.json -o work/plan.snapped.json
```

Дивись на вивід:
- **збіг < 80%** — не той шматок або цитата переказана, повертайся до плану
- **зсув > 15 с** — таймкод транскрипту сильно бреше, перевір, що знайшовся правильний фрагмент
- **тиша перед словом < 0.12 с** — спікер говорить впритул, буфер зачепить попередню фразу

## Крок 3 — різати

```bash
python3 scripts/cut_clips.py work/plan.snapped.json --video "video.mp4" --out clips_out
```

Завжди перекодування (`-c copy` ріже по keyframe і з'їдає перші слова).
Фрагменти склеюються в порядку плану.

Віддаємо **тільки сирі кліпи**: без заголовків, субтитрів, чорних полів 9:16 —
це окремий етап монтажу.

## Крок 4 — перевірка по словах

```bash
python3 scripts/verify_clips.py work/plan.snapped.json --clips clips_out
```

Перетранскрибовує **готові файли** і звіряє з планом (opcodes difflib):

- `delete` — слова були в плані, у файлі їх нема → різ з'їв, треба буфер
- `insert` — у файлі зайві слова → зачепили сусідню фразу
- `replace` — слово почулось інакше → whisper недочув, різ правильний

`--fix` підсуває межі й переписує план; тоді повтори кроки 3-4.
**Здавати можна тільки коли всі ✓ або лишились ⚠, які ти свідомо приймаєш.**

## Коли перенарізати

| симптом | що робити |
|---|---|
| з'їдене перше слово | `snap_clips.py --lead 0.6` на весь план, або `verify_clips.py --fix` точково |
| обірваний кінець | `--tail 0.8` |
| склейка звучить різко | у плані підріж кінець попереднього фрагмента на 1-2 слова |
| знайшовся не той шматок | вузьке вікно: `--window 30`, або уточни `start` у плані |

```
smart-clipping/
├── SKILL.md
└── scripts/
    ├── parse_transcript.py    ← читає txt / srt / vtt / «Спікер (00:12:04):»
    ├── validate_plan.py       ← ФАЗА 1: цитати справді є в транскрипті
    ├── transcribe_source.py   ← ФАЗА 2: пословний транскрипт відео
    ├── snap_clips.py          ← ФАЗА 2: різи по межах слів
    ├── cut_clips.py           ← ФАЗА 2: нарізка + склейка
    ├── verify_clips.py        ← ФАЗА 2: перевірка готових файлів
    ├── analyze_examples.py    ← розбір готових прикладів клієнта (опційно)
    └── textmatch.py           ← спільне зіставлення тексту
```
